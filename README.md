# 🐘 코끼리 보드

리더워크샵 Day 2 "커스텀 코끼리 진단"을 위한 **실시간 키워드 매핑 보드**입니다.
가운데 5칸(🐘 코끼리 · 🐟 죽은 물고기 · 🤮 토하기 · 🐦 파랑새 · 🌱 새싹)에 풀의 카드를 놓으면
같은 조 사람들 화면에 즉시 반영됩니다. 로그인 없이 **조 번호 + 이름**만으로 참여합니다.

> **v1.1** — 조 번호 입장(N개 조, 기본 30), 휴대폰 완전 지원(탭해서 놓기), 운영자 페이지 `/admin`.
> **v1.1.1** — 이름 입력이 선택 사항이 되어 **키보드 없이 탭만으로** 입장됩니다(자동 별칭 `익명-XXX`).
> 입장 후 **⋯ → 이름 바꾸기**.

---

## 빠른 시작 (로컬)

```bash
npm install
npm run dev          # http://localhost:3000
```

환경변수 없이 바로 뜹니다. 이때는 **로컬 모드**로 동작합니다(아래 참고).

---

## 배포 3단계

### 1. Supabase 프로젝트 만들고 스키마 실행

1. [supabase.com](https://supabase.com)에서 새 프로젝트를 만듭니다.
2. 대시보드 왼쪽 **SQL Editor** → **New query**.
3. 이 저장소의 [`supabase/schema.sql`](supabase/schema.sql) 내용을 **전부 붙여넣고 Run**.
   테이블 7개(boards·participants·keywords·placements·votes·notes·events),
   Realtime 발행 설정, 익명 읽기·쓰기 RLS 정책이 한 번에 만들어집니다.
4. **Project Settings → API**에서 `Project URL`과 `anon public` 키를 복사해 둡니다.

### 2. 환경변수 설정

프로젝트 루트에 `.env.local`을 만들고 방금 복사한 값을 넣습니다.

```bash
cp .env.example .env.local
```

```env
NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...
```

워크샵 설정 두 개도 여기에 넣습니다(둘 다 선택).

```env
NEXT_PUBLIC_TEAM_COUNT=30        # 조 수 (기본 30, 1~99)
NEXT_PUBLIC_OPERATOR_KEY=...     # /admin 입장 키 (비우면 게이트 없음)
```

`npm run dev`를 다시 실행하면 상단바 배지가 **실시간**으로 바뀝니다.
Supabase 두 값 중 하나라도 비어 있으면 자동으로 로컬 모드로 떨어집니다.
`NEXT_PUBLIC_*`는 빌드 시점에 번들에 박히므로, 값을 바꾸면 **다시 빌드**해야 합니다.

### 3. Vercel 배포

1. [vercel.com](https://vercel.com) → **Add New… → Project** → 이 저장소를 Import.
2. **Environment Variables**에 위 두 개를 그대로 추가합니다
   (`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`).
   Framework Preset은 Next.js로 자동 인식되고 빌드 설정은 손댈 게 없습니다.
3. **Deploy**. 끝나면 나오는 주소를 열어 보드를 만들고, `/b/{slug}` 링크를 참가자에게 공유하면 됩니다.

## 로컬 모드 vs 실시간 모드

| | 로컬 모드 | 실시간 모드 |
|---|---|---|
| 조건 | 환경변수 없음 | `NEXT_PUBLIC_SUPABASE_URL` + `NEXT_PUBLIC_SUPABASE_ANON_KEY` 둘 다 있음 |
| 저장 | 브라우저 `localStorage` | Supabase(Postgres) |
| 동기화 | `BroadcastChannel` — **같은 브라우저의 다른 탭끼리만** | Supabase Realtime — 모든 기기·모든 사람 |
| 용도 | 혼자 흐름 확인, 데모, 개발 | 리허설·워크샵 당일 |

> **주의**: 로컬 모드에서 만든 보드는 그 브라우저에만 있습니다.
> 링크를 다른 사람에게 보내도 "보드를 찾을 수 없습니다"가 뜹니다.
> 여러 기기에서 같이 쓰려면 반드시 위 2단계까지 해서 실시간 모드로 띄우세요.

## 호스트 권한

- **조 보드(`t01…`)**: 호스트는 운영자입니다. 조 보드는 아무도 갖지 않은 임의 토큰으로 만들어지고,
  `/admin`의 **호스트 권한 이 브라우저에 가져오기**로 운영자 브라우저가 모든 조의 호스트가 됩니다.
- **레거시 보드**: 보드를 **만든 브라우저**에 `host_token`이 저장되고, 그 브라우저가 호스트가 됩니다.
- 호스트만 할 수 있는 것: 단계 전환(배치→투표→발표), 보드 잠금, 되돌리기, 전체 초기화,
  축 표시 토글, 🤮 숨김, 타이머 시작·정지, 축 필터, 카드의 축·예상 칸 보기.
- **다른 기기에서 호스트가 되려면**: 호스트 브라우저의 **⋯ 메뉴 → 호스트 토큰 복사** 로 토큰을 받아,
  그 기기의 **⋯ 메뉴 → 호스트 토큰 입력** 에 붙여넣습니다.
  (진행자가 노트북에서 보드를 만들고 태블릿에서 진행하는 경우에 씁니다. 토큰은 공유하지 마세요.)

## 입장 흐름 (v1.1)

워크샵 하나에 **N개 조**가 있고(기본 30, `NEXT_PUBLIC_TEAM_COUNT`), 조마다 보드가 하나씩 고정돼 있습니다.

| 조 | 주소 | 보드 제목 |
|---|---|---|
| 1조 | `/b/t01` | `1조` |
| 7조 | `/b/t07` | `7조` |
| 30조 | `/b/t30` | `30조` |

1. 참가자가 `/`를 엽니다. **조 번호 칩**을 하나 고르고 **입장하기**를 누릅니다.
   **이름은 선택 사항**입니다(예: 제일런). 비워 두면 `익명-XXX` 자동 별칭이 붙으므로
   **키보드 없이 탭만으로** 입장할 수 있습니다(원격 격리 브라우저에서 키 입력이 막히는 경우 대비).
   들어온 뒤 **⋯ → 이름 바꾸기**로 언제든 바꿀 수 있습니다.
2. 그 조의 보드가 없으면 그 자리에서 만들어지고(시드 46장 포함), 있으면 그대로 들어갑니다.
   여러 명이 동시에 처음 눌러도 보드는 하나만 만들어집니다.
3. 마지막에 고른 조·이름은 브라우저에 기억돼 다음 방문 때 미리 선택됩니다.
4. `/b/t07` 링크를 직접 받은 사람은 **이름만** 넣으면 됩니다(조는 주소로 정해지고, 이름은 여기서도 선택).
5. 역할(전략팀/임원/리더) 입력은 없어졌습니다. 홈에서 보드를 새로 만드는 기능도 없습니다
   (운영자가 `/admin`에서 준비합니다). `/b/{임의slug}` 형태의 예전 보드는 그대로 열립니다.

**호스트(진행 권한)는 조 보드를 만든 사람이 아니라 운영자입니다.** 조 보드는 아무도 갖지 않은
임의의 호스트 토큰을 가지고 만들어지고, 운영자가 `/admin`에서 한 번에 가져갑니다(아래).

## 운영자 페이지 `/admin`

진행자(전략팀) 전용 화면입니다. 30개 조를 한 화면에서 준비·전환·집계·내보내기 합니다.

```
/admin?key=<NEXT_PUBLIC_OPERATOR_KEY>
```

- **키**: `NEXT_PUBLIC_OPERATOR_KEY`. 주소의 `?key=`로 넘기거나 화면에서 입력하면 브라우저에 기억됩니다.
  환경변수를 비워 두면 게이트가 꺼지고 경고 문구가 뜹니다.
  ⚠ **이 키는 보안 장치가 아닙니다.** 값이 클라이언트 번들에 들어가고, Supabase RLS도 익명 허용이라
  링크를 아는 사람은 어차피 읽고 쓸 수 있습니다. 실수로 들어가는 것을 막는 구분일 뿐입니다.

| 섹션 | 하는 일 |
|---|---|
| **보드 준비** | `t01…tNN` 중 없는 것만 만들기(여러 번 눌러도 안전) · 조별 링크와 복사 버튼 · 배치 카드 수/46 · 득표 · 마지막 활동 · 단계 · 잠금 · **링크 목록 CSV**(인쇄·QR용) |
| **호스트 권한 가져오기** | 각 보드의 `settings.host_token`(Supabase는 `host_token` 컬럼)을 읽어 이 브라우저에 저장합니다. 누르고 나면 **모든 조의 호스트**가 됩니다 |
| **전체 단계 전환** | 배치 / 투표 / 발표를 **모든 조에 한 번에**. 전체 잠금·해제, 🤮 전체 숨김·표시. 확인 창 + 진행 표시 |
| **전체 집계** | 5초마다 자동 갱신(끄고 수동 새로고침도 가능). 카드×칸 빈도표(행마다 최다 칸 강조, 열 머리글로 정렬), 칸 합계, 전 조 합산 상위 득표, 카드별 예상≠실제 비율, 조별 진행률 |
| **일괄 내보내기** | `elephant-board_all_{yyyyMMdd-HHmm}.csv`(모든 조의 카드 한 파일) · `.json`(모든 조 스냅샷) |
| **위험 구역** | 모든 조 초기화 — 2단계 확인(경고 → `초기화` 입력) |

데스크톱 기준이지만 폰에서도 열립니다(섹션이 세로로 쌓이고 표만 가로로 스크롤).

## 진행 흐름 (S1 팀 리허설 스크립트)

1. 진행자가 `/admin`에서 **조 보드 만들기/확인**과 **호스트 권한 가져오기**를 누른다.
2. 각자 `/`에서 자기 **조 번호 + 이름**을 넣고 들어온다. 상단바에 👥 인원이 뜬다.
3. 왼쪽 풀의 46장을 끌어(또는 카드를 눌러 칸을 골라) 5칸에 놓는다. 남이 놓으면 내 화면에서도 카드가 움직이고 토스트가 뜬다.
4. 오른쪽 패널에서 **칸별 개수 · 축 분포 · 예상≠실제**를 보며 이야기한다. 항목을 누르면 그 카드가 강조된다.
5. 호스트가 **투표** 단계로 바꾼다. 각자 점 스티커 3개를 카드에 붙인다. 상위 5개가 패널에 뜬다.
6. 호스트가 **발표** 단계로 잠근 뒤 **발표 모드**를 켠다. 풀·패널이 사라지고 보드만 크게 보인다(🤮 숨김 가능).
7. ⋯ 메뉴에서 **JSON · CSV · PNG**로 내보낸다. 링크를 닫았다 열어도 상태는 그대로다.

타이머(⏱)는 언제든 쓸 수 있습니다. 호스트가 15/30분 또는 직접 입력한 시간으로 시작하면
모든 참가자가 같은 남은 시간을 봅니다.

## 화면·조작

- **반응형**: 데스크톱은 풀·보드·패널 3단. 태블릿 가로(≤1180px)는 풀이 하단 서랍, 패널이 우측 시트로 접힙니다.
- **휴대폰(≤768px)도 완전히 쓸 수 있습니다** (v1.1). 칸이 세로로 쌓이고, 풀은 하단 서랍(45vh),
  집계는 📊 버튼 → 시트, 상단바는 조 이름·단계·👥·⋯ 로 줄어듭니다(발표 모드는 폰에서 제공하지 않습니다).
- **탭해서 놓기**: 카드를 누르면 5칸 + 풀로 되돌리기 + 상세 보기가 있는 시트가 열립니다.
  폰에서는 탭이 기본 경로이고, 태블릿·데스크톱에서는 **길게 누르기**나 카드 상세의
  **다른 칸으로 이동**으로 같은 시트를 열 수 있습니다. 드래그도 그대로 됩니다.
- **키보드 없이도 됩니다**: 입장·카드 배치·투표·집계까지 탭만으로 끝납니다.
  (`+ 빈 카드`와 근거 메모만 타이핑이 필요합니다.)
- **키보드**: Tab으로 카드를 고르고 `1`~`5`로 칸 이동(코끼리·죽은물고기·토하기·파랑새·새싹), `0`으로 풀 복귀.
  `Enter`/`Space`는 이동 시트(거기서 상세로 갈 수 있습니다), `Esc`는 발표 모드 종료,
  `Ctrl/Cmd+Z`는 호스트 되돌리기.
- **터치**: 길게 눌러 끌면 드래그, 짧게 누르면 이동 시트(폰) / 카드 상세(태블릿)입니다.

## 개발

```bash
npm run dev         # 개발 서버
npm run build       # 프로덕션 빌드
npm run start       # 빌드 결과 실행
npm run lint        # ESLint
npm run typecheck   # tsc --noEmit
```

- 상태는 `src/store/board.ts` 하나(zustand).
- DB 접근은 `src/lib/db.ts` 한 곳에서만. `db.local.ts`(localStorage+BroadcastChannel)와
  `db.supabase.ts`(Postgres+Realtime)가 같은 `BoardAdapter` 인터페이스를 구현합니다.
- 시드 카드 46장·축·칸 정의는 `src/lib/seed.ts`와 `src/lib/design.ts`에 있습니다.
- 자세한 구현 결정과 브리프와의 차이는 [`NOTES.md`](NOTES.md)를 보세요.

## 아직 없는 것 (2차 범위)

> 방 다중화 + 전체 집계 화면(BRIEF §2 S2)은 v1.1의 조 보드 + `/admin`으로 들어왔습니다.

- **개인 모드 → 공개 → 합의** 흐름과 역할별(임원 vs 리더) 인식 갭 (§2 S3)
- 사진 업로드 → OCR로 카드 자동 생성
- 상위 카드 5개를 문장으로 요약해 주는 한 줄 요약
- 카드 색 태그(★ 등 참가자 임의 표시)
- `host_token` 서버 검증(Edge Function). 지금은 클라이언트에서만 확인하고,
  RLS는 "slug를 아는 사람은 읽기·쓰기 가능"인 익명 허용 정책입니다.
